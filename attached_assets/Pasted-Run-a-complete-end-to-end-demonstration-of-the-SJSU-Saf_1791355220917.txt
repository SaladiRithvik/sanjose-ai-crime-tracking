Run a complete end-to-end demonstration of the SJSU SafeMap workflow before demo day.

Do not simply describe the workflow or run code-level tests. Use the actual app interface in a browser and verify the full user experience.

Demonstration steps:

1. Submit a new safety report from the public report form.
- Use a realistic synthetic report.
- Include a category, description, valid map location, date/time, and any required fields.
- Clearly mark the report as demo/test data if the app supports that.
- Submit the report.

2. Verify the report enters the analyst review page.
- Confirm the report appears with a Pending Review status.
- Confirm the analyst can view the description, category, location, date/time, anonymity setting, and any uploaded image or details.
- Confirm the report is not visible on the public map while it is pending.

3. Test the approval workflow.
- From the analyst page, approve the submitted report.
- Confirm the report status changes to Approved.
- Return to the map.
- Confirm the approved report appears on the map at the correct location.
- Confirm the approved report increases the map’s approved-report total.

4. Test the denial workflow separately.
- Submit a second synthetic report with a different description and location.
- Confirm it enters Pending Review and does not appear on the map.
- From the analyst page, deny the report.
- Select or assign the archive reason “False Report” or the appropriate denial reason.
- Confirm the status changes to Denied or Archived.
- Confirm the denied report does not appear on the map and does not increase the approved-report total.

5. Test incomplete information.
- Submit or create a third report missing a critical field, especially location.
- Confirm it cannot be approved or displayed on the map.
- Confirm the analyst can mark it as “Missing Critical Information” or keep it Pending Review.
- Confirm it does not appear on the map.

6. Verify the map rules.
- Only Approved reports should appear on the public map.
- Pending, Denied, Archived, False Report, Resolved, and Missing Critical Information reports must be excluded.
- The map total must count Approved reports only.
- Confirm the report markers, locations, filters, and popups work correctly.
- Confirm the legend and report-volume shading still function correctly.
- Confirm clicking a cluster immediately zooms into the cluster without opening a large dropdown or confusing popup.

7. Verify the full workflow on both views.
- Test the workflow from the landing page.
- Test the analyst review workflow from the analyst page.
- Test the final approved and denied results from the public map.
- Check both SJSU Campus and Downtown views if the report locations support them.
- Test the layout on desktop and mobile widths.

If any step fails, fix the issue in the existing app and rerun the complete demonstration from the beginning. Do not stop after identifying a problem.

At the end, provide a concise test summary showing:

- Report submitted successfully
- Pending review confirmed
- Approval tested
- Approved report added to map
- Denial tested
- Denied report excluded from map
- Missing-location report blocked
- Approved total updated correctly
- Desktop and mobile checks completed

The goal is to confirm that the app is ready for a live demo: a report is submitted, reviewed by an analyst, approved reports appear on the map, and denied or incomplete reports remain excluded.
